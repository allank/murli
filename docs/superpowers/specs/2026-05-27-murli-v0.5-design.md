# murli v0.5 — Stateful Friendliness: Design Spec

**Date:** 2026-05-27  
**Status:** Approved  
**Milestone:** v0.5 — Stateful Friendliness

---

## Goal

Add a profile system that makes repeated agent use cheaper. Agents call `profile save` once, `profile use` to set a default, and every subsequent invocation picks up stored flag values automatically — no repeated `--region`, `--token`, or `--output` flags on every call.

---

## Architecture

No new packages. All new types live in the `murli` core package. Adapter wiring lands in `cobra/`, `cli/v2/`, `cli/v3/`. The profile subcommand group is auto-mounted by all three adapters in `Enable()`/`Wrap()` — same pattern as `describe`.

## Feature 1: Core Types and Storage

### New file: `profiles.go`

```go
// Profile holds a named set of flag values.
type Profile struct {
    Flags map[string]string `json:"flags"`
}

// ProfileStore is the on-disk representation of all saved profiles for a tool.
type ProfileStore struct {
    Default  string             `json:"default,omitempty"`
    Profiles map[string]Profile `json:"profiles"`
}
```

### Storage location

`~/.<toolname>/profiles.json` — where `<toolname>` is the CLI binary's name as registered with the framework (e.g., `~/.mytool/profiles.json`). The format is stable and human-readable. The file and its parent directory are created on first `profile save`; if the file does not exist, all read operations return empty results without error.

### Core functions

```go
// ProfilePath returns the path to the profiles file for the named tool.
func ProfilePath(toolName string) string

// LoadProfileStore reads the profile store from disk.
// Returns an empty store (not an error) if the file does not exist.
func LoadProfileStore(toolName string) (*ProfileStore, error)

// Save writes the store back to disk, creating the directory if needed.
func (s *ProfileStore) Save(toolName string) error

// Get returns the named profile. Returns nil, false if not found.
func (s *ProfileStore) Get(name string) (Profile, bool)

// Set adds or replaces a named profile.
func (s *ProfileStore) Set(name string, p Profile)

// Delete removes a profile. No-op if not found.
func (s *ProfileStore) Delete(name string)

// SetDefault marks a profile as the default.
// Returns an error if the named profile does not exist.
func (s *ProfileStore) SetDefault(name string) error

// Names returns all profile names in sorted order.
func (s *ProfileStore) Names() []string
```

### `FlagAnnotation` change

Add one field to `FlagAnnotation` in `metadata.go`:

```go
Profileable bool `json:"profileable,omitempty"`
```

Zero by default — opt-in only. The existing `ApplyFlagAnnotation` function propagates this to `FlagSchema`.

### `FlagSchema` change

Add the matching field to `FlagSchema` in `schema.go`:

```go
Profileable bool `json:"profileable,omitempty"`
```

Surfaced in `--schema` and `describe` output so agents know which flags can appear in profiles before ever running `profile save`.

## Feature 2: Profile Subcommand Group

Auto-mounted by all three adapters inside `Enable()`/`Wrap()`. If a `profile` command is already present on the root, skip (idempotent — same guard as `describe`).

### `--profile <name>` flag

Registered as a **persistent root flag** (cobra) or **root-level flag** (v2/v3). String type, empty default. Excluded from `--schema` and `describe` flag lists (infrastructure flag, same treatment as `--schema`, `--force`, `--dry-run`).

### Subcommands

**`profile save <name>`**

Reads all root persistent flags that are:
1. Marked `Profileable: true` in `FlagAnnotation`, AND
2. Were explicitly set this invocation (`Changed == true` in cobra; `IsSet()` in v2/v3)

Saves only what was explicitly passed — does not snapshot defaults. To save `--region us-east-1` into a profile named `production`:

```
mytool --region us-east-1 --token abc profile save production
```

Error if no profileable flags were explicitly set this invocation (whether because no flags are annotated `Profileable: true`, or because none were passed) → structured `user_error`:
```json
{
  "status": "error",
  "error_type": "user_error",
  "message": "no profileable flags were set",
  "suggestion": "Pass at least one profileable flag (e.g. --region) when running profile save. Use --schema to see which flags are profileable.",
  "recoverable": true
}
```

**`profile use <name>`**

Sets the named profile as the default in the store. Future invocations apply it automatically without `--profile`. Error if the named profile does not exist → structured `not_found` error with `ExitNotFound (5)`.

**`profile list`**

Lists all saved profiles. Marks the default with `*`. In agent mode, emits JSON:
```json
{"profiles": ["production", "staging"], "default": "production"}
```
In TTY mode, plain text:
```
  production *
  staging
```

**`profile show <name>`**

Prints the flag values stored in the named profile. Error if not found → `not_found`.

Agent mode:
```json
{"name": "production", "flags": {"region": "us-east-1", "token": "abc"}}
```

TTY mode: plain text key=value pairs.

**`profile delete <name>`**

Removes the named profile. If it was the default, clears the default. Error if not found → `not_found`.

### Error types

| Situation | `error_type` | Exit code |
|---|---|---|
| Profile not found | `not_found` | `ExitNotFound` (5) |
| No profileable flags set on `profile save` | `user_error` | `ExitUserError` (1) |
| Disk read/write failure | `tool_error` | `ExitToolError` (2) |

## Feature 3: Profile Application

When any non-profile command runs, murli checks for an active profile and applies stored flag values **before calling the original action**. This happens at the top of every wrapped action, after framework flag parsing.

### Resolution order

1. `--profile <name>` explicitly passed → use that profile
2. No `--profile` → check `store.Default` → use that profile
3. No default, no flag → no-op, proceed normally

### Application logic

For each flag name/value pair in the active profile:
- Look up the flag on the root command's persistent flags
- If it **was not explicitly set** this invocation → apply the stored string value via the flag's `Set` method
- If it **was explicitly set** → leave it alone (explicit flag always wins)

This means `--profile production` sets `--region us-east-1` as a default, but `--region eu-west-1` on the command line still takes precedence.

### Per-adapter mechanism

**cobra:**
```go
f := cmd.Root().PersistentFlags().Lookup(flagName)
if f != nil && !f.Changed {
    _ = f.Value.Set(storedValue)
}
```

**cli/v2:**
```go
// Walk lineage to root context; apply to root
rootCtx := ctx.Lineage()[len(ctx.Lineage())-1]
if !rootCtx.IsSet(flagName) {
    _ = rootCtx.Set(flagName, storedValue)
}
```

**cli/v3:**
```go
root := c.Root()
if !root.IsSet(flagName) {
    _ = root.Set(flagName, storedValue)
}
```

### Exemptions

Profile subcommands (`profile save`, `profile use`, `profile list`, `profile show`, `profile delete`) skip profile application entirely — they act on the store, not on the tool's business logic.

## Feature 4: Describe Output Integration

### `ProfilesInfo` struct (schema.go)

```go
// ProfilesInfo describes the profile system state for agent consumption.
// Included in DescribeOutput when the tool supports profiles.
type ProfilesInfo struct {
    Available        []string `json:"available,omitempty"`
    Default          string   `json:"default,omitempty"`
    ProfileableFlags []string `json:"profileable_flags,omitempty"`
}
```

### `DescribeOutput` change

```go
Profiles *ProfilesInfo `json:"profiles,omitempty"`
```

Example describe output:
```json
{
  "name": "mytool",
  "profiles": {
    "available": ["production", "staging"],
    "default": "production",
    "profileable_flags": ["region", "token", "output"]
  }
}
```

`profileable_flags` is always present (collected by scanning root persistent flags for `Profileable: true`) so agents know what can be profiled even before any profile is saved. `available` and `default` are omitted when no profiles exist yet.

### `Capabilities` change

```go
Profiles bool `json:"profiles"`
```

Always `true` for any murli v0.5-wrapped tool. Agents can gate on this before attempting profile subcommands.

## Testing Strategy

### Core package (`profiles_test.go`)

- `LoadProfileStore` returns empty store (not error) when file does not exist
- `Save` creates the parent directory and file if absent
- `Set`/`Get`/`Delete` round-trip correctly
- `Delete` on a non-existent name is a no-op (no error)
- `SetDefault` succeeds when profile exists; errors when profile does not exist
- `SetDefault` on the currently-set default is idempotent
- Deleting the default profile clears `Default` in the store
- `Names` returns profiles in sorted order
- `ProfilePath` resolves `~/.<toolname>/profiles.json` correctly

### Core package (`murli_test.go`)

- `FlagAnnotation.Profileable` marshals/unmarshals correctly
- `ApplyFlagAnnotation` propagates `Profileable: true` to `FlagSchema`
- `ApplyFlagAnnotation` does not set `Profileable: true` when annotation has `false` (already zero)

### Adapter tests (all three — parallel structure)

**Flag registration:**
- `--profile` flag present on root command after `Enable()`/`Wrap()`
- `--profile` absent from `--schema` flags list (infrastructure flag)
- `--profile` absent from `describe` flags list

**`profile save`:**
- Saves only Changed profileable flags; ignores non-profileable Changed flags
- Saves only Changed flags; ignores profileable flags that were not set
- Returns structured `user_error` when no profileable flags were Changed
- Overwrites existing profile with same name

**`profile use`:**
- Sets default in store; subsequent load confirms default
- Returns structured `not_found` error for non-existent profile name

**`profile list`:**
- Returns JSON with `profiles` array and `default` field in agent mode
- Marks default correctly
- Returns empty list when no profiles exist (no error)

**`profile show`:**
- Returns stored flags as JSON in agent mode
- Returns `not_found` for non-existent profile

**`profile delete`:**
- Removes profile from store
- Clears default when the deleted profile was the default
- Returns `not_found` for non-existent profile

**Profile application:**
- Stored flag value applied when root persistent flag not explicitly set
- Explicit flag on command line beats stored profile value
- Default profile auto-applied when no `--profile` passed
- `--profile <name>` overrides default profile for single invocation
- Profile subcommands skip profile application
- No-op when no profile is active and no default is set

**Describe output:**
- `capabilities.profiles` is `true`
- `profiles.profileable_flags` lists root persistent flags with `Profileable: true`
- `profiles.available` and `profiles.default` present when profiles exist
- `profiles.available` and `profiles.default` absent when no profiles exist
- `profiles.profileable_flags` present even when no profiles exist

## Breaking Changes

None. All new fields in `FlagAnnotation` and `FlagSchema` are zero-valued by default. `Profiles *ProfilesInfo` on `DescribeOutput` uses `omitempty`. `Capabilities.Profiles` is additive. Existing code compiles and behaves identically.

---

## What is explicitly out of scope

- Per-subcommand profiles (v0.5 profiles are root persistent flags only)
- Profile encryption or secret storage (use `Sensitive: true` as advisory; storage is plaintext)
- Profile import/export
- Profile versioning or migration
- Shell completion for profile names
- `--profile` on non-root persistent flags
